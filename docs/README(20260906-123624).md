# Modular AI Document Workspace

## Development Plan Documentation

This documentation defines the initial plan for a reusable AI application platform with a document-centered React interface and a framework-neutral Python application layer.

The platform is intended to support corporate applications while keeping the reusable foundation independent from any single agent framework, model provider, cloud platform, or document editor.

## Primary goals

- Provide a polished document workspace using React and Tiptap Core.
- Provide an AI conversation and action interface using an open-source UI layer.
- Allow Databricks notebooks to call the same Python application used by the web interface.
- Allow AWS, Databricks, or future agent frameworks to be attached through adapters.
- Use permissively licensed open-source components for the reusable foundation.
- Preserve a planned integration point for Cordis as the future plugin-management layer.
- Support locally hosted models so development can proceed before company AI gateway access is available.
- Switch among local, company-hosted, and authorized external models through configuration rather than workflow rewrites.
- Keep corporate-specific code, data, prompts, and configuration separate from reusable platform code.

## Current technology direction

| Area | Initial choice | Architectural treatment |
| --- | --- | --- |
| Web application | React with TypeScript | Application shell |
| Document interface | Tiptap Core | Hidden behind a document adapter |
| Agent interface | CopilotKit open-source SDK or equivalent | Hidden behind an agent-UI wrapper |
| Python API | FastAPI | Stable application entry point |
| Notebook access | Python client over HTTPS | Calls the same application API |
| Agent frameworks | AWS, Databricks, or others | Replaceable adapters |
| Model providers | Local, company gateway, or authorized external | Selected through a provider-neutral model adapter |
| Plugin management | Cordis, planned | Added after module contracts stabilize |
| Data exchange | Versioned JSON events and commands | Framework-neutral contracts |

## Guiding principle

The application must depend on its own stable contracts. It must not make the React interface, Databricks notebooks, or shared application core depend directly on one agent framework or model provider. A local model must be available as an early-development option while preserving the company AI gateway as the intended corporate production path when access becomes available.
