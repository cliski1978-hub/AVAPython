# Phase 5.55 — Conversation Folder Sidebar UX

The conversation sidebar now groups the existing canonical conversation list into flat, backend-ordered folder sections and an `Ungrouped` section. Conversations within each section retain the server-provided conversation order. Search continues to query the typed, title-only backend search API; the matching results are grouped by their existing `folder_id`, and empty search groups are omitted.

Folder state lives in `ConversationProvider` alongside the one canonical conversation collection. The provider loads the folder list independently from conversations and messages. If folder loading fails, it keeps the flat conversation list available and shows a safe message. Create and rename use the Phase 5.54 typed client operations and refresh the canonical folder list after success. Delete requires confirmation and explains that conversations survive and move to `Ungrouped`; success removes the folder and patches affected conversation metadata without reloading messages. A folder 404 triggers reconciliation of folder and assignment metadata.

Conversation action menus include `Move to folder`, with server-ordered folder choices and `Ungrouped`. Assignment changes only the target conversation's `folderId` after the server confirms it. Failed moves keep the original membership. Neither folder mutations nor expand/collapse change selection, transcript messages, or run state. Existing per-conversation run observation remains outside the sidebar, so background streaming continues while membership changes.

Folder sections are expanded by default. Their accessible toggle buttons control ephemeral component state; it is not persisted. Rename/delete conversation actions remain available within folder groups. Archived and pinned conversations remain in their existing population and order. No drag/drop, nested folders, Projects, folder search, archive changes, or backend/API-client production changes were added.
