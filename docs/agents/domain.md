# Domain docs

## Single-context layout

- Domain vocabulary: root `CONTEXT.md`.
- Architecture decisions: `docs/adr/`.

Before exploring, read `CONTEXT.md` and any ADRs relevant
to the work.

If these documents do not exist, proceed silently.
The domain-modeling skill creates them as terms and
decisions are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts
in issues, proposals, hypotheses, and tests.

If a concept is missing, reconsider whether it fits the
project's language or note the gap for domain-modeling.

## Decisions

Explicitly identify any conflict with an existing ADR
and explain why the decision should be reconsidered.
